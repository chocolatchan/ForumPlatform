## 1. Executive Summary

Task 031.2.12 removes the hard-coded development database targets from the two live outbox test modules and makes their database-backed tests fail closed when no disposable test database is configured.

The remediation is implemented in the two identified test modules plus one small shared test helper:

- `tests/test_outbox_concurrency_live.py`
- `tests/test_outbox_hardening.py`
- `tests/outbox_pg_isolation.py` (new)

Database-backed tests now require explicit `TEST_*_DATABASE_URL` environment variables. Missing or blank variables cause the affected tests to skip; present but malformed or unsafe variables raise `pytest.UsageError` during collection, before any database connection can be opened. No test falls back to `.env`, Compose defaults, service settings, or a development database URL.

The hardening module no longer uses the applications' global database managers for test SQL. Its in-process ASGI calls are patched to the validated test managers, and the former live Search HTTP call was replaced with an in-process ASGI transport. Cleanup is scoped to identifiers generated by each test and runs from `finally` blocks; worker HTTP clients and fixture-owned database managers are closed on failure paths as well.

No disposable PostgreSQL test databases were configured in this environment. Therefore, the actual PostgreSQL integration tests were **not executed**, and no connection was made to any application database. The offline policy, skip, cleanup-helper, lint, formatting, and static-type validations passed.

## 3. Isolation Policy Implemented

### 3.1 Explicit environment variables

The tests require the following dedicated variables:

| Test database | Environment variable |
|---|---|
| Content outbox | `TEST_CONTENT_DATABASE_URL` |
| Notification consumer | `TEST_NOTIFICATIONS_DATABASE_URL` |
| Search consumer | `TEST_SEARCH_DATABASE_URL` |

`TEST_NOTIFICATIONS_DATABASE_URL` follows the existing repository convention used by `tests/test_email_worker_lease_pg.py`. The former unused Interactions URL was removed because these tests do not operate on the Interactions database.

There is no fallback to application settings, `.env`, Compose service URLs, default development URLs, or another service's test database.

### 3.2 Validation before connection

`tests/outbox_pg_isolation.py` validates a URL without opening a connection. A target is rejected when:

- The value is set but empty after trimming.
- The URL cannot be parsed.
- The scheme is not PostgreSQL with `postgresql` or `postgresql+asyncpg`.
- No explicit database name is present.
- The database name is a known live application database or begins with `forum_`.
- The database name does not match the disposable naming policy.

Accepted database names must match `test_*` or `stress_*` using lowercase letters, digits, and underscores. A plain `postgresql://` URL is normalized to `postgresql+asyncpg://` before use.

Validation occurs at module import/collection time. An unsafe or malformed configured target raises `pytest.UsageError` before any fixture can create an engine or open a connection. Missing or blank variables return `None`, and the affected tests are skipped individually.

### 3.3 Per-test skip behavior

Skip markers are applied to the database-backed tests rather than to the whole module. This allows the offline policy and cleanup tests to run even when no PostgreSQL test database is configured.

### 3.4 Application database patching

For in-process ASGI requests, the test modules patch the application module globals:

- `src.services.content.app.content_db`
- `src.services.notification.app.notification_db`
- `src.services.search.app.search_db`

Each is replaced with a `DatabaseSessionManager` built from the validated test URL for the duration of the test. The Search loss-of-response test now uses an in-process `httpx.ASGITransport` with a fault-injecting wrapper; it no longer targets a running container or a live service endpoint.

### 3.5 Scoped cleanup and failure-path closure

- Fixtures close their database managers in `finally`.
- Outbox workers are stopped in `finally`, closing their HTTP clients.
- Cleanup statements are scoped to test-generated UUIDs and keys:
  - Content outbox event IDs.
  - Content thread and category IDs, plus the created consumed-event ID.
  - Notification event ID, recipient ID, comment target ID, and related email-delivery records.
  - Search event ID and thread source ID.
- `cleanup_test_rows()` executes only the supplied scoped `delete(...)` statements and is a no-op when called without statements, preventing accidental table-wide cleanup.

## 7. Limitations and Follow-Up

2. **Strict naming is intentional.** Operators must name test databases with a `test_` or `stress_` prefix. Live names and all `forum_`-prefixed names are rejected.
3. **Actual SQL cleanup was not exercised.** The cleanup statements are scoped to test-created identifiers, but real deletion behavior can only be confirmed in a disposable PostgreSQL run.
4. **Other PostgreSQL tests are outside scope.** This task only hardened the two identified outbox modules and did not modify other database-backed tests or runtime code.
